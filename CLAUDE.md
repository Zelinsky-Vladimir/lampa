```
mobile/mobile.js   iOS platform layer: the same window.api on Capacitor (Filesystem, native HTTP, App, StatusBar)
mobile/mobile.css  phone styles (safe areas, touch)
ios/               Xcode project (Capacitor 8, Swift Package Manager, no CocoaPods)
ios/App/App/WebAuth.swift  local plugin `WebAuth.start({url, scheme})` (ASWebAuthenticationSession) + LampaBridgeViewController that registers the local plugins
ios/App/App/AppleSignIn.swift  local plugin `AppleSignIn.authorize({nonce})` → `{idToken}` (sends SHA-256 of the nonce to Apple); App.entitlements enables Sign in with Apple
scripts/build-mobile.js  assembles www/ for Capacitor (src + mobile + fflate + icon), syncs iOS version from package.json
supabase/schema.sql      database schema (records + RLS + newer-wins trigger, book_files quota ledger, book_quotas per-account overrides, delete_account(); the old `books` storage bucket is unused)
supabase/functions/books Edge Function for book files in Cloudflare R2: list / upload (quota check + presigned PUT) / confirm (HEAD, real size) / download (presigned GET) / delete / deleteAll
```

## Cloud sync (Supabase)

- Project ref `lxztjateewlladvgzzlj` ("Lampa Server", Frankfurt). URL and the publishable key are in `src/cloud.js` (public by design). Never use or ask for the service-role/secret key or the database password.
- Apply schema changes with the Supabase CLI (login is stored on his machine; on a new machine run `npx supabase login` in a terminal he can type into): `npx supabase db query --linked --project-ref lxztjateewlladvgzzlj -f supabase/schema.sql`.
- Auth: Google provider (Google Cloud project "Lampa", OAuth app published) and email/password with "Confirm email" off. Redirect URLs allowed: `lampa://auth-callback` (desktop) and `io.github.zelinskyvladimir.lampa://auth-callback` (iOS).
- Records: kind `lib` (id = `size|title|author`, library entry + reading position), `mark` (bookmark/note id), `shelf` (reading-list book id). Newer `updated_at` wins (server trigger). Records arriving from the server are stamped `r` and not pushed back. Book files live in Cloudflare R2 bucket `lampa-books` at `<user id>/<sha256-16>.<ext>` (≤ 50 MB each). Only the `books` Edge Function holds the R2 keys (Supabase function secrets `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`, set by him); clients get 15-minute presigned URLs. `public.book_files` is the per-user ledger (RLS: read own only, writes only from the function); a file counts once `confirm` has checked its real size in R2. Quota per account: 100 MB by default (`BOOK_QUOTA_MB` function secret overrides the default), per-account overrides in `public.book_quotas` (`user_id`, `quota_mb`; RLS on, no policies, only the function reads it; his account `zelinskiy.v97@gmail.com` has 300); over quota the function answers 413 `QUOTA` and the app shows `syncQuotaFull` once and keeps the book local; `confirm` also answers `EMPTY` (422) or `TOO_LARGE` (413), and one failing book never stops the others from uploading. The bucket is in the EU jurisdiction (`R2_JURISDICTION`, default `eu`, host `<account>.eu.r2.cloudflarestorage.com`). Object sizes come from ListObjectsV2, never from a HEAD: Cloudflare compresses text objects such as FB2 on the fly and drops Content-Length. Deploy: `npx supabase functions deploy books --project-ref lxztjateewlladvgzzlj --no-verify-jwt --use-api` (the function checks the user token itself).
- Feature flags live in the user's Supabase `app_metadata.features` (only the server can set them) and reach the app with the session (`cloud.session.user.features`). `translate` turns on translation on the desktop; without it the selection-bar button and the "Translate into" setting are hidden. Only his account (zelinskiy.v97@gmail.com) has it, set with `update auth.users set raw_app_meta_data = raw_app_meta_data || '{"features":["translate"]}' where email = …`. iOS always translates on the device.
- Sync runs on start, on window focus, a few seconds after changes and every minute. The reading position is merged on its own: `lib` records carry `posAt` (when the reader really moved the place: more than a third of a page, within 6 s of a touch, key or wheel, not within 1.5 s of a resize, or during autoscroll — a relayout on resume or rotation never counts, or the device that just woke up would beat the one that was read), and the later `posAt` wins even when the record as a whole is older, so opening a book on one device (which bumps `openedAt`) never overwrites a newer place from another. Opening a book waits up to 1.5 s for a sync already in flight. Coming back to the app counts as opening the book again (`posAtOpen` is reset), and it syncs at once, after 5 s and after 15 s, so a push still on its way from the other device is caught; changes go up 2 s after they settle. A synced jump keeps the other device's `posAt` and becomes the anchor of any resize still settling (`resizeAnchor`), so the relayout cannot pull the page back. If the open book moved on another device: when nothing moved here since opening it jumps there with a toast (`syncJumped`), otherwise a banner offers to jump. On iOS the app asks for background time (`SceneDelegate`, 15 s) when it leaves the screen so the last push gets through.
